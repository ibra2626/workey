## 2026-11-02 — WKY-24: MCP catalog tools, bookEnum removal, agent guide (implementation)
- Context: give the AI client MCP tools to write/read the source catalog and record unit results, move the plan/outline MCP schemas to the catalog shape, drop the fixed book enum, rewrite the agent guide, and restore `internal/mcpserver` + `internal/apidoc` against the catalog `plan.Item`/notation (WKY-22 scope split). WKY-22 defined `SaveSourceRequest` for this task to consume; the catalog write/read **service** path did not exist yet.
- Decision:
  - **Catalog service path lives in `internal/plan` (not transport), implemented here as the first consumer; WKY-25 reuses it.** New `internal/plan/sources.go`: `SaveSource(ctx, source, SaveSourceRequest)` and `Sources(ctx) → CatalogView`. SaveSource replaces a source whole, keyed by `key`; it **reconciles by ordinal** (sections on section ordinal, units on section ordinal + unit ordinal) using the store's `Update*`/`Insert*`/`Delete*` helpers so a kept unit keeps its id — and therefore its `unit_progress` — while dropped sections/units are deleted (cascading progress). Alternative — `ReplaceSections`/`ReplaceUnits` (delete-all + re-insert) — rejected: it wipes `unit_progress`, violating "re-extracting a source keeps the user's done/D-Y-B".
  - **Idempotent + audited like SavePlan.** A structural snapshot excluding ids/timestamps drives both the no-op (`Unchanged`) check and the single `audit_log` row (entity `source`, create/update, before/after JSON, request hash); `idempotency_key` replay via the shared `replay`/`remember`. save_source itself never writes `unit_progress`.
  - **kind/location_unit validated against the store's CHECK sets** in `validateSaveSource` (book/video/course/other; page/minute/lesson/other) so a bad value is a typed field error, not a raw SQLite CHECK mapped to "internal". Section/unit ordinals must be positive and unique; ranges paired/ordered.
  - **Three new MCP tools:** `get_sources` (catalog with unit ids), `save_source`, `set_unit_result` (wraps WKY-23 `SetUnitResult`). `bookEnum` removed; item schema → source_key/section_ordinal/unit_from/to/loc_from/to; session `kind` relaxed to a free label (known values as description examples, no enum); outline `dgs_question_*` → `question_*`; save_source carries source kind/location_unit enums. mapError unchanged: an unknown source_key surfaces as `validation_failed` with field code `unknown_source`.
  - **AgentGuide drops the fixed book list.** `Books` → `SourceKinds` + `LocationUnits` (SessionKinds kept); rules/workflow rewritten for the extract → save_source → get_sources → user-corrects → plan → set_unit_result flow, "references only, no topic/question content" kept, all DGS/five-book wording removed. The agent owns structure extraction; the user owns correction via the web Kaynaklar page (WKY-26).
  - **Cross-transport test gated, not deleted.** `TestMCPWebWorkflow` + `TestVisualReview` need `internal/web` (red by design until WKY-26/27), so they and the `web` import moved behind `//go:build webworkflow`; the default MCP test build is web-free (`newMCP`). WKY-28 re-enables them. Alternative — leave them in the default build — rejected: the whole `mcpserver` test package would fail to compile, so none of the acceptance tests could run.
  - **docs/mcp.md hand-written sections updated now; the two verbatim-synced blocks (study-contract, planning-inputs) are regenerated by `internal/web/views` (red) and re-synced in WKY-26/27.** apidoc examples are already on the new ItemView shape, so that regeneration is correct.
- Alternatives: put catalog reconciliation in the transport (rejected — business logic belongs in `internal/plan`); hand-regenerate the escaped-markdown doc blocks (rejected — risks diverging from the generator, whose sync test is in the red web layer).
- Consequences: `internal/plan`, `internal/store`, `internal/mcpserver`, `internal/apidoc` build (normal + `CGO_ENABLED=0`), vet and test green; `internal/api` non-test now builds too (apidoc side effect). Remaining red by design: `internal/web/views` (→ web, cmd) for WKY-26/27 and `internal/api` _test files for WKY-25. gofmt clean on LF-normalized content (working-tree CRLF is the `core.autocrlf` checkout artifact). No commit/push.

## 2026-11-02 — WKY-23: unit progress + D/Y/B service path (implementation)
- Context: a business-logic path to mark a unit "bitti" with optional D/Y/B, fully independent of session completion (user decision 2026-11-02, recorded in the v2 direction entry and the feature README). The store already carried `unit_progress` CRUD and `UnitProgressByUnit`/`UnitProgressBySource` from WKY-21; this task adds the service and the missing reads.
- Decision:
  - **`Service.SetUnitResult(ctx, source, UnitResultRequest{UnitID, Done, Correct/Wrong/Blank *int})`** in a new `internal/plan/units.go`. `done=true` upserts the progress row; `done=false` clears it (undo). Returns a `UnitResultView` with the unit's catalog identity, resolved notation (`M1·3, Antrenman 1`) and current result.
  - **First-completion done_at is sticky.** On a repeat or a D/Y/B change the original `done_at` is kept (the unit stays "done since" its first mark); only undo→redo re-stamps it. Alternative — restamp on every write — rejected: the done-at is the moment the user first finished.
  - **Idempotent, audited like completion.** A no-op (same stored state, compared over done_at + D/Y/B + completed_source) writes nothing and no audit row; a real set/undo writes one `audit_log` row (entity `unit`, action `complete`/`undo` reused from `complete.go`, before/after JSON, source, NULL request hash — no request payload to hash, mirroring session completion).
  - **D/Y/B are non-negative and null for video units.** Structural `checkNonNeg` rejects a negative count (`CodeInvalid`); a `video`-kind source rejects any D/Y/B (`CodeInvalid`) but can still be marked done with them null. Kind is read via a new `store.UnitByID` (unit joined to section+source). No CHECK that D/Y/B sum to anything — the user reports what they did.
  - **No coupling to session completion.** `SetUnitResult` never touches `sessions`; `Complete`/`Undo` never touch `unit_progress`. Verified by a two-direction independence test.
  - **Reads for WKY-26/27.** `UnitResults(unitIDs)` (map keyed by unit id, absent = not done) and `SourceProgress()`/`SectionProgress()` (done-count + D/Y/B sums per source/section). The aggregation is SQL in the store (`UnitProgressByUnits`, `UnitProgressTotalsBySource/BySection` with `COALESCE(SUM(...),0)` so a null D/Y/B counts as 0 but the row still counts toward done-count); the plan layer maps store aggregates to its own `ProgressTotals`/`UnitResult` types so the web layer never sees store types.
- Alternatives: aggregate in Go from `UnitProgressBySource` (rejected — the task wants store aggregate queries, and `GROUP BY` is cheaper and clearer); restamp done_at every write (rejected, above); silently ignore D/Y/B on a video unit (rejected — rejecting it surfaces the mistake to the agent/UI).
- Consequences: `internal/plan` + `internal/store` stay green — `go test ./internal/plan/... ./internal/store/...`, `go vet`, normal + `CGO_ENABLED=0` builds, gofmt-clean on the changed files. The whole tree stays red by design until WKY-28 (transport/web expose this). No commit/push.

## 2026-11-02 — WKY-22: plan domain bound to the catalog (implementation)
- Context: rebind `internal/plan` to the catalog `store.SessionItem`/`TopicGroup` from WKY-21. Changing `plan.Item` breaks every downstream layer that renders the v1 book/chapter/page/konu/soru/antrenman concepts; those concepts no longer exist.
- Decision:
  - **Items reference the source by its stable `key`, the section by `ordinal`, the unit range by 1-based unit ordinals within the section, and a raw location range in the source's location unit.** `plan.Item = {SourceKey, SectionOrdinal *int, UnitFrom/UnitTo *int, LocFrom/LocTo *int}`. The service resolves key→id and section ordinal→id at write time (a per-tx `catalog` snapshot in `resolve.go`). Alternative — items carry raw ids — rejected: the agent writes by human-readable key; ids are internal.
  - **An item needs a unit range or a location range; a unit range requires a section.** Structural checks in `validate.go`; catalog-reference checks in the service against the stored catalog, as typed `ValidationError`s with codes `unknown_source` / `unknown_section` / `unit_out_of_range` (unit range vs the section's unit ordinals).
  - **`kind` is a free label** — the `validKinds` enum gate is dropped (store imposes no CHECK); the `KindAksam/UzunBlok/Deneme` constants stay as display hints. `TopicGroupInput`/read models rename `DGSQuestion*`/`DGSMin/Max` → `Question*`/`QuestionMin/Max`.
  - **Notation is resolved-data-in, string-out** (`notation.go`): `FormatRef(ItemRef)` renders `M1·4, Antrenman 5–7, Test 1–2` — source key · section ordinal, then unit label groups (consecutive same-label units collapse to a number range using each unit's `number`), then the location range with a unit prefix (page→"s. ", minute→"dk ", lesson→"ders ", other→none). U+00B7 / U+2013 preserved; multi-item join with " · ". Read models resolve items via the catalog (`read.go`, `ItemView` with source/section/unit display fields).
  - **Session-study flow adapted minimally, not redesigned:** `Bookmark.ResumePage` is kept but is now a location value validated against the item's loc range (the v1 konu/soru sub-range narrowing is gone); the stage gate (konu/soru/yanlis_defteri for akşam, calisma otherwise) stays. Fuller stage semantics under the catalog are revisited in WKY-27.
  - **Catalog write-path input types** (`SaveSourceRequest{Source, Sections[]}` with units per section) are defined now for WKY-24/25 to share, though unused this task.
  - **Scope split (user, 2026-11-02):** WKY-22 keeps only `internal/plan` + `internal/store` building and green. The downstream compile-and-rebind of `internal/mcpserver`+`internal/apidoc` (WKY-24), `internal/api` (WKY-25) and `internal/web`(+views) (WKY-26/27) moves to those tasks; the whole-tree `go build ./...` is intentionally red until WKY-28.
- Alternatives: items carry raw ids (rejected, above); full web/transport compile-fix now (rejected by the user — it would gut real logic owned by WKY-24..27); leave the study flow fully to a later task (rejected — it lives in `internal/plan`, which must compile).
- Consequences: `go test ./internal/plan/... ./internal/store/...` green, `go vet` clean, both packages build normal + `CGO_ENABLED=0`, gofmt-clean on LF content. `testdata/sample-*.json` moved to the catalog shape (so the deferred api/mcp/web tests that read them stay red). No commit/push.

## 2026-11-02 — WKY-21: catalog schema and store layer (implementation)
- Context: first task of the v2 catalog feature — rebuild the embedded schema and the `internal/store` API for the direction below. No committed data to preserve, so `0001_init.sql` is rewritten in place (not a second migration); `0002_study_flow.sql` is kept unchanged (it references only `sessions`).
- Decision:
  - **Table shapes.** `sources(key UNIQUE, name, kind CHECK book/video/course/other, location_unit CHECK page/minute/lesson/other, ordinal, created_at, updated_at)`; `sections(source_id FK ON DELETE CASCADE, ordinal, name, loc_from/to, CHECK range, UNIQUE(source_id,ordinal))`; `units(section_id FK ON DELETE CASCADE, ordinal, label free TEXT (no enum), number, loc_from/to, CHECK range, UNIQUE(section_id,ordinal))`; `unit_progress(unit_id PK FK ON DELETE CASCADE, done_at, correct/wrong/blank each CHECK >= 0, completed_source NOT NULL CHECK mcp/api/web)`.
  - **`completed_source` is NOT NULL on `unit_progress`** (every write is attributable; mirrors the audit-source invariant), while D/Y/B stay nullable so video units record "done" with no numbers. A progress row's existence = the unit is done.
  - **`session_items` references only:** `source_id` NOT NULL FK, `section_id` nullable FK, `unit_from/to`, `loc_from/to`, both range-checked, `UNIQUE(session_id,ordinal)`. `source_id`/`section_id` use the default NO ACTION (a source referenced by a plan item cannot be deleted out from under it); only the session→item edge cascades.
  - **`sessions.kind` CHECK dropped** (open TEXT, still NOT NULL — callers may pass ''); `topic_groups.dgs_question_*` → `question_*`; `TopicGroup.DGSQuestion*` Go fields → `Question*`.
  - **Store API gives both reconcile and replace paths.** `UpdateSection`/`UpdateUnit` change content in place keeping the id (and so the unit's progress); `ReplaceSections`/`ReplaceUnits` delete+reinsert (new ids, progress dropped) for a full rewrite. WKY-22 chooses per case. `UpsertUnitProgress` (INSERT … ON CONFLICT(unit_id)) makes marking-done idempotent; reads are `UnitProgressByUnit` and `UnitProgressBySource` (joined, keyed by unit id).
- Alternatives: progress columns on `units` (rejected — a save_source rewrite would wipe them; already in the direction entry); a single `ReplaceSourceStructure` helper (rejected — it forces delete+reinsert, losing progress; the granular update helpers let WKY-22 preserve unit ids); nullable `completed_source` (rejected — breaks attributability).
- Consequences: `internal/plan` and everything above it do not compile at the end of WKY-21 (the `SessionItem` and `TopicGroup` field changes) — expected, rebound in WKY-22. Store package builds (normal + `CGO_ENABLED=0`), `go vet ./internal/store/...` and `go test ./internal/store/...` pass with table tests for each new table, cascade, UNIQUE/CHECK violations, the keep-id progress-survival case, and progress upsert/read.

## 2026-11-02 — v2 kaynak kataloğu: genel kaynak/bölüm/birim modeli
- Context: workey v1 hard-codes DGS and five books (M1/M2/M3/G1/G2) — `session_items.book` CHECK + `bookEnum` + book-specific `konu/soru/antrenman` columns, `topic_groups.dgs_question_*`, `sessions.kind` enum. The system will open to several people, each studying a different exam with their own books, videos, YouTube playlists or Udemy courses. The AI agent should extract each source's structure; the user studies by *units* ("Antrenman", "Test", "Föy", "Ders"), which v1 could not represent. Brain-vault decision 2026-11-01 chose Approach A (source catalog) over B (free unit list per session) and C (single JSON blob). User clarified 2026-11-02: the existing 149-session DGS plan has not been started and is disposable (no migration), and unit completion is independent of session completion.
- Decision:
  - **Concept model Kaynak → Bölüm → Birim.** `sources` (key, name, kind: book/video/course/other, location_unit: page/minute/lesson/other), `sections` (ordinal, name, optional location range), `units` (ordinal, source-supplied `label`, number, optional location range — the code never hard-codes the label words). A `session_items` row references source + section + a unit/location range instead of a fixed book + pages.
  - **Unit progress is a separate table (`unit_progress`), keyed by unit id**, not columns on `units` — so re-writing a source definition (save_source) never wipes the user's done/D-Y-B. Holds `done_at`, optional `correct`/`wrong`/`blank`, `completed_source`.
  - **Unit completion is independent of session completion.** The one-tap session "tamamlandı" moment (PRODUCT.md) stays primary and unchanged; units are a finer optional overlay. Neither triggers the other.
  - **No data migration.** The schema is rebuilt clean (rewrite `0001_init.sql`); a fresh local DB is acceptable because no real plan data exists yet.
  - **Cheap by-products of the clean rebuild:** remove the fixed `book` enum, relax `sessions.kind` to an open label, rename `topic_groups.dgs_question_*` → `question_*`. The fixed exam date / 38-week framing is NOT torn out — it lives in saved plan content (phase dates) and per-install config, so it generalizes without schema work.
  - **Agent owns extraction, user owns correction.** New MCP tools `save_source`/`get_sources`/`set_unit_result`; a new web "Kaynaklar" page lets the user fix the agent's structure (the M1 TOC-vs-heading "+/−" mismatch was only caught by looking). `get_agent_guide`, docs/mcp.md and docs/api.md are rewritten for the catalog flow with no fixed-book wording.
- Alternatives: Approach B, free unit list per session (rejected — source structure not stored, no per-source progress, rewrite at first external user); Approach C, source structure as one JSON blob (rejected — weak per-unit validation/query, fragile D-Y-B binding); unit progress as columns on `units` (rejected — save_source would overwrite progress); keeping the fixed book enum with a generic escape hatch (rejected — the whole point is no code change per exam/source).
- Consequences: planned as feature `.agent/work/workey-v2-katalog/` (WKY-21..28). The v1 item invariant ("store only book, chapter, page ranges") is superseded by the catalog-reference invariant in that folder's README. `internal/plan` will not compile between WKY-21 (store) and WKY-22 (domain rebind); that is expected and noted in the tasks. Nothing implemented yet — this records the accepted direction only.

## 2026-10-26 — WKY-08: Web auth (session cookie, CSRF, Giriş) in `internal/web`
- Context: single-user login protecting all web pages, secure cookies and CSRF on every state-changing htmx request, with no new heavy dependency. Local Windows over plain http on 127.0.0.1 (WKY-12 deploy blocked).
- Decisions:
  - **Password hashing: stdlib `crypto/pbkdf2`** (SHA-256, 600000 iterations, 16-byte random salt, 32-byte key), self-describing encoding `pbkdf2-sha256$iter$b64salt$b64hash` (RawStdEncoding), constant-time compare. Chosen over bcrypt/argon2 (`golang.org/x/crypto`) to avoid a dependency; the encoding carries the iteration count so it can be raised later without breaking stored hashes.
  - **`workey hash-password` disables console echo via `golang.org/x/sys/windows`** (`GetConsoleMode`/`SetConsoleMode`, clear `ENABLE_ECHO_INPUT`), reading from stdin and printing only the hash. `golang.org/x/sys` was already a (verified) indirect dependency, so this adds no new module; `golang.org/x/term` — the idiomatic choice — could not be verified in this offline environment (sum.golang.org unreachable) and bypassing the checksum DB was declined. Non-Windows (`password_other.go`) returns ok=false → caller reads a plain stdin line; a termios implementation can be added for a Linux deploy (WKY-12). `go mod tidy` promoted `x/sys` to a direct dependency.
  - **Signed session cookie (stateless).** Value `b64url(sid(16)||expiryUnix(8)) + "." + b64url(HMAC-SHA256(WORKEY_SESSION_KEY, payload))`; the MAC covers the expiry so it cannot be extended. Flags `HttpOnly`, `Secure` (from `WORKEY_COOKIE_SECURE`, default true — browsers accept Secure on localhost), **`SameSite=Lax`**, `Path=/`, 30-day expiry. No server-side session row (one user; nothing to store/revoke beyond clearing the cookie). Logout sends an expired cookie.
  - **CSRF: keyed per-session token + cross-origin protection.** Token = `b64url(HMAC-SHA256(key, "csrf"||sid))`, derived (no storage), stable for the session, placed on `<body>` via `hx-headers` so every htmx request sends `X-CSRF-Token`; `requireCSRF` checks it (constant-time) on every non-GET web route. Additionally `http.CrossOriginProtection` (Go 1.25+) wraps the whole web mux — this is what protects the pre-session `POST /giris` (origin/Sec-Fetch check), so login needs no token. `Layout` gained a `csrf` parameter; `Placeholder` and the page handler thread it through.
  - **Web mux mounted at `/`.** `internal/web` now exposes `Auth` + `Auth.Handler()` (its own `ServeMux` wrapped in cross-origin protection) instead of `AddRoutes(mux)`; `cmd/workey` mounts it at `/` and the more specific `/healthz`, `/api/v1/`, `/mcp` patterns still win. API/MCP stay Bearer-only and are not cookie-authenticated or cross-origin-wrapped. Static assets and `/giris` are the only public web routes; `requireAuth` redirects an unauthenticated page GET to `/giris` (303) and returns 401 for other methods.
  - **Dev-open mode.** `WORKEY_DEV=1` with no password hash makes `requireAuth` a pass-through (fixed dev sid for a stable CSRF token) and `/giris` redirects to `/`, so UI tasks (WKY-09+) run without secrets; `config.Load` already allows empty secrets only in dev. When a session key is unset, `NewAuth` generates an ephemeral one.
  - **Login throttling:** global in-memory backoff after 3 failed attempts, growing 1s per failure to a 30s cap; a single-user local guard against rapid guessing, not a distributed defence.
- Alternatives: bcrypt/argon2 (rejected — adds a dependency; PBKDF2 is in the stdlib and adequate for a single strong local password); `golang.org/x/term` for no-echo (rejected — unverifiable offline; reused the already-verified `x/sys`); server-side session store (rejected — one user, nothing to revoke); double-submit cookie CSRF without a key (rejected — keyed HMAC token can't be forged and needs no storage); relying on `SameSite` alone for CSRF (rejected — task requires an explicit token; cross-origin protection adds defence in depth); `SameSite=Strict` (rejected — Lax keeps top-level navigations working and the token is the real guard).
- Consequences: `internal/web` owns auth/session/CSRF; screens (WKY-09/10/11) render behind `requireAuth` and read the CSRF token from the layout. `cmd/workey` gains the `hash-password` subcommand and two tiny platform files. A Linux deploy (WKY-12) should add a termios no-echo path and reconsider `x/term`. Focused tests, vet, gofmt and normal + `CGO_ENABLED=0` builds pass with Go 1.27.3; the Giriş screen was verified live at 390 and 1280 over http on 127.0.0.1.

## 2026-10-26 — WKY-07: MCP server (Streamable HTTP) in `internal/mcpserver`
- Context: expose the plan service to an AI client as MCP tools in the same binary, preserving the one business-logic layer and reusing `internal/httpx`.
- Decisions:
  - **SDK `github.com/modelcontextprotocol/go-sdk` v1.8.0** (latest stable; v1.1.0 was the first v1 GA). Mounted at `/mcp` via `mcp.NewStreamableHTTPHandler(getServer, nil)` (stateful default, SSE), wrapped with `httpx.SecurityHeaders(httpx.BearerAuth(token, …))`. It pulls in `github.com/google/jsonschema-go` v0.4.3 (the SDK's schema inference/validation library, 2020-12 draft).
  - **The `/mcp` Bearer token is `WORKEY_API_TOKEN`** — the same secret as `/api/v1`. A single-user local app has no reason to issue two tokens; config stays unchanged. A separate `WORKEY_MCP_TOKEN` can be split out later without touching the handler (it already takes the token as an argument).
  - **Six tools, mirroring the service 1:1:** `get_plan(from,to)`, `save_plan(SavePlanRequest)`, `complete_session(session_id, done=true)`, `get_outline()`, `save_outline(SaveOutlineRequest)`, `get_progress()`. Chose **`get_outline`/`save_outline`** over the task's alternative split (`get_topic_groups`/`save_topic_groups`/`save_phases`) because the service exposes outline reads/writes as one unit (`Outline`/`SaveOutline`) and REST already does the same — fewer tools, no logic split. `complete_session` addresses the session by the `id` returned in `get_plan` (as REST does), while `save_plan`'s `makeup_of` stays a `(date, start_time)` slot.

## 2026-10-26 — WKY-03: SQLite store on modernc.org/sqlite, embedded migrations
- Context: v1 needs a persistence layer. The stack is a single self-contained binary for local Windows (Linux later), so a CGO SQLite driver (mattn/go-sqlite3) would force a C toolchain and break `CGO_ENABLED=0` cross-builds.
- Decisions:
  - **Driver `modernc.org/sqlite` v1.61.0** (pure Go, no CGO): registered under database/sql name `sqlite`; builds with `CGO_ENABLED=0`, keeping the single-binary promise.
  - **Connection:** opened via DSN pragmas `busy_timeout(5000)`, `foreign_keys(1)`, `journal_mode(WAL)` so every connection carries them. `SetMaxOpenConns(1)` — the single-writer pattern: for a single-user local app one connection serialises writes and (with WAL + busy timeout) avoids "database is locked" without a separate reader pool.

## 2026-10-26 — WKY-04: plan write path (`internal/plan`), store composability
- Context: `internal/plan` is the single business-logic layer for plan writes (validation, freezing, idempotency, audit, notation). It composes `internal/store` query helpers inside one transaction.
- Decisions:
  - **`store.WithTx` callback now takes `*sql.Tx`** instead of the unexported `dbtx` interface. External packages cannot name `dbtx`, so they could not build a `func(tx dbtx) error`; `*sql.Tx` satisfies the (still unexported) `dbtx` that every query helper accepts, so plan can compose helpers in a transaction. `store_test.go` updated to match. The query helpers keep taking `dbtx` so `*sql.DB` still works for read-only paths.
  - **`makeup_of` is referenced by `(date, start_time)` (`SlotRef`), not by raw id.** The write API is declarative and matches sessions by that slot; the service resolves the slot to the missed session's stored id and requires it to be past and uncompleted. The external caller (AI via MCP/API) never sees internal ids. (DECISIONS 2026-10-26 "Missed sessions" said the AI "may set `makeup_of` to the missed session's id"; the id is the stored form, the slot is the write-API form that resolves to it.)
  - **Range replace is declarative and frozen-aware.** For dates in `[from,to]` that are today-or-later (Europe/Istanbul via the injectable clock), the open sessions become exactly the request's set, matched by slot: matched → update-in-place (id kept) or unchanged, absent → deleted. Past-dated and completed sessions are frozen (never updated/deleted); an incoming session targeting one is returned in `skipped[]` with a machine reason, not applied.
  - **Idempotency has two layers.** Without a key, re-applying the same payload yields all-unchanged and zero audit rows (content equality check per session). With `idempotency_key`, the canonical request hash + stored response are kept in `idempotency_keys`; a repeat replays the stored response, and the same key with a different payload returns `ErrIdempotencyConflict`.
  - **Item replacement, not item diffing.** On update, a session's items are deleted and re-inserted with ordinals 0..n; simpler than per-item diff and correct under the `UNIQUE(session_id, ordinal)` constraint.
  - **Typed errors.** `ValidationError` carries `FieldError{path, code, message}` (stable machine codes) so REST/MCP render without re-checking; store-dependent checks (unknown topic-group key, invalid makeup target, referenced-topic-group delete) produce the same typed errors. Structural validation (`validate.go`) is store-free.
  - **Outline (`SaveOutline`)** replaces phases and topic groups by key (create/update/unchanged/delete), idempotent and audited; deleting a topic group still referenced by sessions fails with code `referenced` and rolls the whole transaction back.
  - **New store helpers** (persistence only, no rules): `catalog.go` adds `Phase`/`TopicGroup` with list/insert/update-by-key/delete-by-key, `TopicGroupByKey`, `CountSessionsByTopicGroup`; `queries.go` adds `UpdateSession`, `DeleteSession`, `DeleteSessionItems`, `SessionByDateAndTime`.
- Alternatives: export `dbtx` as `DBTX` (rejected — passing the concrete `*sql.Tx` is simpler and leaks nothing); reference makeup by id in the write API (rejected — exposes internal ids to the AI/API); per-item diff on update (rejected — more code for no user-visible gain); a separate idempotency table scope per source (rejected — the key is caller-chosen and global is enough for one user).
- Consequences: all plan write rules live here and nowhere else (REST/MCP/web will only parse+call+render). The `testdata/` fixtures (`sample-week.json`, `sample-outline.json`) are labelled sample data for tests and demos, not real plan content.
